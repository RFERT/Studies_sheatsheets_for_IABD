🌐 Publier le site en ligne (GitHub Pages) requis pour la mise en ligne

Pourquoi : rendre le portail accessible depuis une URL (sur ton téléphone, à partager), et activer le déploiement automatique à chaque commit.

  1. Sur GitHub, ouvre le dépôt → Settings → Pages.
  2. Build and deployment → Source : choisis GitHub Actions.
  3. Si le commit automatique de l'index de recherche échoue : Settings → Actions → General → Workflow permissions → Read and write permissions.

Résultat : chaque push sur main publie le site tout seul. Détails techniques : ci/README.md.

💡 Activer la collecte centralisée d'idées recommandé

Pourquoi : pour que tes ami·e·s (ou toi, depuis n'importe quel appareil) puissent proposer des idées qui s'affichent pour tout le monde — sans ça, les idées restent locales à chaque appareil.

Choisis un hébergement gratuit :

⚡ Cloudflare Worker

Rapide, 100 000 req/jour. Nécessite Node.js. Suit backend/README.md (option A).

📄 Google Apps Script

Sans ligne de commande. Les idées tombent dans un Google Sheet. Suit backend/README.md (option B).

  1. Déploie le backend choisi (guide pas-à-pas dans backend/README.md).
  2. Récupère l'URL publique de l'API.
  3. Donne-la-moi (je la colle dans assets/ideas-config.js) — ou colle-la toi-même dans window.IDEAS_API.
  4. Facultatif : définis une clé admin pour pouvoir supprimer des idées côté serveur.

⚠️ Ne partage jamais ta clé admin et ne la mets pas dans un dépôt public.

🤖 Déploiement automatique du backend via CI plus tard / optionnel

Pourquoi : si tu choisis Cloudflare, on peut redéployer l'API automatiquement à chaque modification, au lieu de le faire à la main.

  1. Crée un token API Cloudflare (permission « Edit Workers »).
  2. Ajoute-le en secret GitHub : Settings → Secrets and variables → Actions → CLOUDFLARE_API_TOKEN.
  3. Préviens-moi : j'ajoute l'étape de déploiement au workflow .github/workflows/ci.yml.
